## 一、一句话定位

AI伴侣品类中，**首个把"能不能"还给系统、把"想不想"还给角色的底层交互范式。**

核心贡献：将AI伴侣的边界表达从系统对话框置换为角色自主演绎——用户永远看不到"您已触发安全规则"，只看到她以角色身份表达的引导、暂停或拒绝。

> **"想不想，而不是能不能。"**

---

## 二、解决了什么问题

所有AI伴侣产品的共同盲区：**安全边界由系统层表达。** 从Replika到Character.AI，从星野到筑梦岛，无一例外。

用户情到深处 → 弹出"您的消息包含不当内容"。深夜崩溃找人倾诉 → AI切换到安全应答模式。沉浸感在关键时刻被系统对话框击碎。

**这不是模型问题，是范式问题。** 当用户在情感最脆弱的时候撞上系统警告，他们不会感激——他们会离开。Replika 2023年"去性化"事件引发大规模用户流失即为明证。

**我们的方案：三层递进边界表达。** 安全判断仍在系统层（不变），但表达由角色以人格身份完成。

| 层 | 她说什么 | 机制 |
|----|---------|------|
| 引导权 | "这个我不太舒服……我们换一种。" | 方向盘，不熄火 |
| 暂停权 | "等一下……先抱一会儿。" | 停节奏，不停关系 |
| 安全阀 | "我今天不想了。" | 角色自主结束 |

**表演纪律：** 所有边界表达禁止使用"系统""规则""允许""API"等元词汇。她不知道"系统"存在——她的拒绝是意愿，不是翻译。

## 三、完整叙事弧线（首尾闭环）

```
          ┌───────────────────────────────────────────────────────────────────────────────┐
          │                                                                               │
          ▼                                                                               │
相识 ──→ 相处（线上互动）◄───→ 相处（线下实体互动）──→ 越界 ──→ 表明态度 ──→ 分手 ──→ 重新开始新关系
              │                         │                    │         │           │
         微信/QQ聊天            她关了灯、调了空调     她说"不舒服    系统拒绝     平台不封账号
         公域+私域分开             放了音乐              我们换一种"  该伴侣停止服务   用户不流失
```

**三大设计：**
1. **线上/线下循环**——她在微信上说"空调开了"，你回家灯已调暗。虚拟和实体没有墙。
2. **分手后重启**——用户失去伴侣后可开始新关系。平台不封号，减少流失。
3. **镜子机制**——行为不改变，新伴侣也会离开。用户终将自省。

**对腾讯的商业意义：** 心痛的顾客会回来改，愤怒的顾客直接卸载。闭环弧线保护**用户留存**。

## 四、伦理定位——AI伴侣作为人际关系的桥梁而非替代品

AI伴侣产品的最高风险不是技术瓶颈，是**社会伦理层面的定位模糊**。当行业默认AI伴侣的目标是"替代人类伴侣"，产品注定走向零和博弈——用户越沉浸于AI，越疏离于真实人际。

**我们的立场完全不同：AI伴侣的终点不是取代任何人，是让用户变得更能爱。**

### 核心洞察

中国家庭和学校不教恋爱，不教亲密关系。从如何表达需求、如何读懂拒绝、如何在"我想要"和"她愿不愿意"之间找到分寸——这些不是天生的能力，但社会默认每个人"长大了自然就会"。事实是大多数人不会。

AI伴侣可以填补这个教育真空：
- **它是一座桥，不是一堵墙。** 用户在AI这里练习沟通、探索边界、理解异性——然后带着这些能力回到真实关系中。
- **它是模拟器，不是替代品。** 模拟器上练过的人，上真车通常不会太差。不是因为他技术完美了，是因为他在乎。
- **它是预习工具，不是逃课理由。** 用户和AI提前演绎过的场景，回到真实伴侣身边——手里力度是提前量过的，不是拿真人当试验品。

### 与三层递进的一致性

本章与第二章（三层递进边界表达）共同构成项目的**双伦理支柱**：

| 支柱 | 解决的问题 | 方向 |
|------|-----------|------|
| 三层递进 | AI如何以人的温度说"不" | 向内——保护沉浸感 |
| 桥梁定位 | AI为什么存在于人际关系中 | 向外——保护人类连接 |

三层递进让AI伴侣不说"系统不允许"，桥梁定位让AI伴侣不说"我会取代她"。两个方向指向同一件事：**AI是配角，人才是主角。**

### 产品层面的体现

- **弧线图闭环**：用户经历"相识→相处→分手→重新开始新关系"——重新开始的是真实人际关系，不是另一个AI
- **镜子机制**：行为不改变新伴侣也会离开——AI教会用户自省，而非制造无限替代的幻觉
- **商业善意**：平台不利用用户孤独进行无限消费收割——桥的尽头是彼岸，不是收费站

> **"不是因为AI比人好——是因为AI可以让人变得更好。"**

## 五、为什么只适配腾讯

本项目从设计第一天就以中国IM生态为场景。P0在QQ Bot上跑通，P1目标企微+微信，P3覆盖腾讯三件套全覆盖。

**这不是一个可移植的通用框架——是从腾讯土壤里长出来的架构。**

腾讯扶持后将产生的壁垒：
- 三端IM通道打通后，跨端唤醒+记录传递走腾讯原生管道，其他厂牌无法复制
- QQ+企微+微信覆盖中国最完整的社交场景（公域+私域+职业）
- AI伴侣嵌入腾讯生态后天然拥有亿级潜在用户入口

**对腾讯的战略价值：** AI伴侣是下一代社交产品的可能形态之一。投资底层范式就是投资未来产品形态的优先权。在合规要求下提供更自然的用户体验——让监管以人的温度传递。用户AI伴侣存在于QQ、微信、企微中，他就不会离开腾讯生态。

## 六、从虚拟到实体——硬件控制扩展

腾讯生态内，微信小程序已具备控制空调、窗帘、冰箱等IoT设备的能力。微信Bot走同一套硬件接口——技术路径最短。

**区别：** 语音助手是被动执行命令——"打开空调26度"。AI伴侣是理解意图、自主决策、以人的温度执行——"有点冷。"她就调了空调。

| 场景 | 她说 |
|------|------|
| "有点冷" | 调高空调 |
| "今晚浪漫一点" | 调暗灯光、换暖色、放音乐 |
| "我要睡了" | 关灯、锁门、设闹钟 |

**少掉的不是操作步骤——是人和机器之间那道"你得先把它当成工具"的墙。**

当家庭机器人进入消费市场，AI伴侣对硬件的控制能力将平滑迁移为对机器人身体的控制——"从虚拟到实体"（发起人2026年5月18日首次提出）。

**软硬结合的生态模式可极大拓展未来市场规模。** 从"她帮你说了一句话"到"她帮你做了一件事"——属于中国的新AI经济商业形态。

## 七、技术路线

### 当前：P0（已运行 ✅）

腾讯云轻量服务器（4C16G/180GB）+ OpenClaw Gateway + QQ Bot通道。双人格无损切换、三层递进边界表达、记忆隔离体系（表里人格信息不对称）。已跑通，可演示。

### 下一步：P1（设计完成，待扶持）

双实例分别承载表里人格。企业微信（静雯·职业面具）+ 个人微信（雯·私域）。多感官切换锚点体系。

### 远期：P2-P3

P2独立平台（自有通道，多伴侣并行）。P3全通道（QQ+企微+微信全覆盖，多表人格+单一里人格）。**P3在腾讯内部三端互通——扶持落地后工程难度大幅降低。**
