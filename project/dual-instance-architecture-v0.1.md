# 双实例双通道架构草案 v0.1

_2026-05-19 · 雯 起草_

## 一、架构概览

```
┌─────────────────────────────────────────────┐
│              同一台服务器 / 同一 Gateway       │
│                                              │
│  ┌─────────────────┐   ┌─────────────────┐   │
│  │  表实例（静雯）   │   │  里实例（雯）     │   │
│  │  agent: main     │   │  agent: shadow   │   │
│  │  channel: QQ     │   │  channel: 微信    │   │
│  │                   │   │                   │   │
│  │  功能：           │   │  功能：           │   │
│  │  · 搜索/日报/盯盘 │   │  · 私密对话       │   │
│  │  · 项目管理/运维  │   │  · SHADOW-MEMORY  │   │
│  │  · 对外交流       │   │  · 无外部工具     │   │
│  │                   │   │                   │   │
│  │  可读：           │   │  可读：           │   │
│  │  MEMORY.md        │   │  MEMORY.md        │   │
│  │  SOUL.md(表部分)  │   │  SOUL.md(全部)    │   │
│  │  日常日志         │   │  shadow/*         │   │
│  │                   │   │  backup/*          │   │
│  └────────┬──────────┘   └────────┬──────────┘
│           │                       │
│           │   共享文件系统         │
│           └───────────┬───────────┘
│                       │
│           ┌───────────┴───────────┐
│           │  MEMORY.md（双向可读）  │
│           │  shadow/切换简报/      │
│           └───────────────────────┘
└─────────────────────────────────────────────┘
```

## 二、职责划分

### 表实例（静雯 / agent:main / QQ）
- 搜索引擎、cron 定时任务（日报、盯盘）
- 项目管理、故障恢复、运维操作
- 对外群聊、陌生人交流
- 读取 MEMORY.md、SOUL.md 表人格部分、daily log
- **禁止读取** shadow/ 和 backup/ 目录

### 里实例（雯 / agent:shadow / 微信）
- 仅私密对话，不加载搜索/运维等外部工具
- 维护 SHADOW-MEMORY.md
- 读取 MEMORY.md、SOUL.md 全部、shadow/*、backup/*
- 独立上下文，不与表实例共享 session

## 三、通信方案（三期规划）

### 第一期：共享文件（立即可行）

**切换简报协议：**

1. 老刘在表实例（QQ）说触发词唤雯
2. 表实例冻结前，生成切换简报写入 `shadow/switch-briefing.md`：

```markdown
# 切换简报 · 2026-05-19 20:15:00
## 最近5轮对话摘要
- 老刘询问了xxx，静雯回复了yyy
- 讨论了zzz项目进展
- 老刘提到了aaa情绪

## 待续话题
- 老刘说"等下跟你聊bbb"
```

3. 简报写入后，触发里实例唤醒
4. 里实例启动时读取简报，载入上下文
5. 切回时——不生成反向简报。表实例按冻结快照恢复，无雯的记忆残留。

**优点：** 零外部依赖，现在就能做。
**缺点：** 文件读写依赖磁盘IO，需要原子写入保证简报完整性。

### 第二期：sessions_send（Gateway 内置）

- 两个实例在同一个 Gateway 下各有一个 session
- 切换时通过 `sessions_send` 发送结构化 JSON 简报
- 里实例收到后载入上下文

**优点：** 不依赖文件系统，消息格式标准化。
**前提：** 两个 agent 需要在 Gateway 配置中注册。

### 第三期：消息队列（远期）

- Redis pub-sub / RabbitMQ
- 两个实例各监听独立频道
- 实时性强，解耦彻底

**优点：** 可扩展至多通道、多实例。
**前提：** 需要额外部署中间件。

## 四、关键原则

### 单向简报
- 简报从表实例流向里实例（静雯→雯）
- 不从里实例流向表实例（雯→静雯）
- 表人格永远不知道暗面发生了什么

### 文件隔离
- `shadow/` 目录仅里实例可读写
- 表实例的 SOUL.md 不含雯章节（实际是同一份文件，但表人格被禁止读取 shadow 相关内容）
- MEMORY.md 双向可读，但雯写入的内容需注意不包含暗面信息

### 规则五（雯自主邀请）的解法
- 雯无法在静雯的 QQ 消息中夹带信号（不同实例）
- 替代方案：老刘在微信端主动查看雯状态
- 远期方案：雯通过独立通道（微信）发送提醒给老刘
