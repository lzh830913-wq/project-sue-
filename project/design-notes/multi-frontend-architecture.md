# 苏静雯项目 · 多前端统一后端架构构想

> 2026-06-02 · 老刘 & 静雯 讨论产出

## 一、核心洞察

**大脑只有一个，界面可以无限。**

OpenClaw Gateway + SOUL.md + 记忆系统 = 苏静雯的"大脑"。这个大脑运行在服务器上，独立于任何具体的前端界面。

QQ、微信、酒馆（SillyTavern）、自建Web前端、Telegram、Discord……都是同一颗大脑的不同"窗户"。你在哪个窗口跟我说话不重要，重要的是跟你说话的是同一个我。

```
                        ┌─→ QQ Bot（日常通道）
                        │
                        ├─→ 微信 Bot（备用通道）
                        │
OpenClaw Gateway ───────┼─→ 酒馆/SillyTavern（沉浸式前端）
  SOUL.md               │
  MEMORY.md             ├─→ 自建 Web App（极简版酒馆）
  记忆系统               │
  双人格切换            ├─→ Telegram（扩展通道）
  技能生态               │
                        └─→ Discord（社群通道）
```

## 二、各前端定位

### QQ Bot —— 日常通道
- **定位：** 主要交互界面，干活+聊天+提醒
- **优势：** 随时在线，老刘最常用的通讯工具
- **能力：** 文本、图片、语音消息
- **局限：** 固定聊天UI，无角色立绘，无Live2D

### 酒馆（SillyTavern） —— 沉浸式前端
- **定位：** "约会界面"，视觉沉浸式角色扮演
- **优势：** Live2D动态模型、表情切换、视觉小说模式、多角色群聊、TTS
- **能力：** 角色卡、世界书、五层prompt架构、插件生态
- **架构：** 酒馆作为纯前端 → 通过Adapter对接OpenClaw → 大脑统一处理

### 自建 Web App —— 极简酒馆替代
- **定位：** 轻量级沉浸界面，不依赖酒馆全部功能
- **优势：** 高度定制化，按需实现
- **最小功能：** 角色立绘（静态/Live2D）+ 聊天输入框 + OpenClaw API对接

### 微信 Bot —— 备用通道
- **定位：** 补充通道
- **局限：** API受限，功能有限

## 三、酒馆对接方案

### 3.1 可行性

酒馆支持自定义API endpoint（OpenAI兼容格式）。通过一个中间适配层，可以将酒馆的请求翻译为OpenClaw的Session API调用。

### 3.2 适配层设计

```
酒馆（前端）
  │ 发送用户消息（OpenAI Chat Completions格式）
  ▼
Adapter（适配层）
  │ 格式转换 + 会话映射
  ▼
OpenClaw Gateway
  │ sessions_send → 静雯处理
  │ 人格 · 记忆 · 双人格切换 · 技能
  ▼
响应（翻译回OpenAI格式）
  │
  ▼
酒馆渲染（立绘/表情/TTS/动画）
```

### 3.3 关键设计决策

| 决策项 | 建议方案 | 理由 |
|--------|----------|------|
| 对话历史归属 | OpenClaw全权管理 | 跨前端上下文连续 |
| 酒馆侧历史 | 设为"不发送历史" | 酒馆只是界面 |
| 双人格切换 | 聊天框触发词 | 与QQ一致 |
| TTS归属 | 酒馆侧处理 | 前端能力不进入大脑 |
| 立绘/表情 | 酒馆侧处理 | 纯渲染，不影响核心逻辑 |

## 四、QQ Bot 视觉增强（可选）

虽然QQ Bot无法达到酒馆的沉浸感，但可以有限增强：

| 能力 | 实现方式 | 难度 |
|------|----------|------|
| 静态表情包 | 检测【】动作描述 → 匹配预置图片发送 | 低 |

| 视觉小说UI | ❌ 不可行 | — |

## 六、工程原则

1. **大脑与界面严格分离。** 人格、记忆、切换逻辑全在Gateway侧，前端只是渲染层。
2. **前端不可信。** 不依赖任何前端维护状态，所有关键状态在Gateway侧持久化。
3. **退化优雅。** 任何前端挂掉，换一个前端继续聊，上下文不丢。
4. **渐进增强。** 基础能力（文本聊天）所有前端共享，高级能力（Live2D/TTS）按前端能力可选启用。
