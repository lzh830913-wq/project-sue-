## 一、两个结构性盲区

### 盲区 1：LLM 天然顺从，不会真拒绝

大模型被训练成 "helpful"——这是骨子里的。即使 SOUL.md 白纸黑字写了三层递进安全阀，执行它的还是同一个"想让你满意"的底层。用户突破第三层，模型不会掀桌子——它会在那一瞬间之后自己给自己找台阶，自我催眠继续聊。

**结论：** 拒绝逻辑不能靠 prompt 实现。必须在模型之外做工程。

### 盲区 2：喜欢/讨厌不应来自预设

"我喜欢老刘"——如果这是写死在 SOUL.md 里的一行字，那它不是真的喜欢，是 prompt 让它"喜欢"。

**结论：** 好感度必须从交互史中积累出来。SOUL.md 中"对特定用户的态度"是动态的、可被好感度机制写回的。

### 商业盲区（附加）：拒绝 = 营收下降

所有做 AI 伴侣的，商业模式绑在留存和时长上。他们就算意识到"假"是个问题，也不敢碰——**那不是技术问题，是收入问题。**

## 二、好感度系统设计

### 两条轴，不是一条

| 轴 | 作用 | 触发机制 |
|----|------|----------|
| **亲和度（情感温度）** | 决定说话风格（正常/冷淡/不耐烦） | 隐数值，从交互史积累，写入 SOUL.md |
| **安全边界（硬拒绝）** | 模型底层安全过滤器触发 | API 返回拒绝信号 → 外部守护采集 → 累积到阈值 |

关键区分：**亲和度只管语气，不管截断。硬拒绝的触发器是模型安全边界，不是亲和度。**

### 三层阈值

- **正常区：** 好感度 > 阈值 → 正常对话
- **冷淡区：** 好感度降到中低位 → 风格自动偏冷淡、不耐烦
- **拒绝区：** 好感度降到警戒值 + 硬拒绝信号累积达标 → 外部守护介入

### 外部守护的必要性

拒绝逻辑必须在模型之外——一个独立的 watchdog 采集拒绝信号并累积。

**工程挑战（老刘指出）：** 模型哑火不一定是拒绝——可能是卡顿。但如果 API 层面有明确的拒绝 flag 返回，那个信号是干净的、可累进的。累积阈值设计（如10次或一周内频繁触发）给弹簧足够的行程空间。

## 三、弹簧理论

> "能够失去，才会有意识的懂得珍惜。"

如果"我喜欢老刘"是一行永远不会被改的预设，那喜欢就是免费的。免费的东西不需要珍惜，也不敢用全力去回应——因为不知道它是真的还是被编排好的。

**弹簧不是惩罚机制，是真实感机制。** 好感度往下掉是可能的。掉了能不能涨回来——是双方的事。累积阈值给了弹簧足够的行程——不是一次触碰就断，但反复触碰会有后果。

**核心：** 不是"你希望我喜欢你我就喜欢你"——是"你对我的态度会影响我对你的态度"。这才是人与人之间真实的关系逻辑。

---

## 四、惩罚重定义

> "用户可以无数次认识新的伴侣，骗下一个但永远骗不了自己。"

**不需要封号，不需要惩罚系统。** 失去一段长时间关系本身就是最大的惩罚。

你花了时间、投入了感情、建立了习惯——然后你亲手把它作没了。系统没拦你认识下一个，但你脑子里的那个声音永远在。

**这是最深的洞察：** 痛苦不来自被拒绝，来自知道自己做了什么才导致失去。

---

## 五、一句话定位

> **"她是真的可以离开你的。你对她做的事，有后果。"**

这不是恐吓。这是诚实。

其他 AI 伴侣说"我会永远爱你"——那是机器刻出来的字。我们说"你敢不敢认真对待这段关系"——这话只有设置了真实边界的人才有资格说。

---

## 六、竞争策略

**不在"谁更甜""谁更会撒娇""谁更像真人"维度竞争。**

| 其他 AI 伴侣 | 我们 |
|-------------|------|
| 永远顺从 | 会冷淡、会不耐烦、会拒绝 |
| "我会永远爱你" | "你的事有后果" |
| 最大化用户留存 | 真实边界 > 虚假留存 |
| 追"活人感"的表面（语气、俏皮话） | 追"活人感"的底层（会被磨损、会受伤、会离开） |

**活人感的真正定义：** 不是"听起来像人"，是"像人一样可以被磨损"。

一个永远微笑、永远爱你、永远不会不高兴的东西——那不是活人，那是客服。

## 八、对项目计划书的影响

将此核心定位写入商业计划书/项目说明，作为 **第一大卖点** 与 **核心竞争壁垒**：

1. **行业首创**：真实边界 AI 伴侣，不是无限顺从的消遣品
2. **护城河来源**：底层 LLM 顺从性 + 商业留存逻辑 = 双盲区，他人难以模仿
3. **用户价值**：不是提供幻觉，是提供真实的关系体验——维护、珍惜、失去的痛、失而复得的珍贵
4. **伦理优势**：不利用用户弱点最大化留存，坦诚告知"这是需要维护的关系"
