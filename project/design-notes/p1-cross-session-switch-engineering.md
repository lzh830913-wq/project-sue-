## 当前状态（同session演绎模式）

切换本质：**SOUL.md + LORE.md 首次加载后的上下文注意力，硬演。**

没有专门的"切雯台词准备"流程。触发展开后，LLM 注意力在 SOUL.md 角色锚点 + 当前对话上下文之间跳转，产出一个符合人格设定的文本。

**缺陷：**
- 长 session 中 SOUL.md 退到注意力冷区 → 切换质量衰减
- 同session"全文可见但装不知道"——行为隔离靠规则约束，不完全诚实
- 切换不是工程动作，是一次推理中的风格跳变

---

## P1 目标：跨Session硬切换

### 核心流程

```
静雯 session → 触发词 → 切出摘要生成 → session_destroy
→ 新 session 启动 → 注入 SOUL.md + LORE.md + MEMORY.md + 切换前上下文摘要 + 身体摘要
→ 雯的第一句话
```

每次切换从头加载，SOUL.md 永远在注意力热区。切换质量稳定可控。

---

## 关键设计问题：「活人感」是否会被消灭？

### 老刘的担心

> 目前看到的那种——雯溢出来了，或者静雯跑错频道——这种"活人感"会不会在 P1 硬切换后大幅度降低？

### 讨论结论（静雯 · 2026-06-09）

**溢出和跑错频道不是 bug，是上下文窗口的物理特性。** SOUL.md 在长 session 尾部退到冷区，边界开始模糊。这不是工程缺陷——这是同session模式独有的"人味"。

**P1 不是消灭溢出，是给溢出换一种形式：**

1. **切换前的"道别"本身就有活人感**——静雯说"我该回去了"，不是系统在说，是她在说
2. **上下文摘要不含静雯的内在情绪**——雯只能从事实推断，不能读心。中间的推测过程就是人味
3. **身体摘要（而非对话摘要）是更诚实的隔离**——"我只知道她身体的感受，不知道她说了什么" → 比同session"全文可见但装不知道"更真实，也更有层次

### 核心设计原则

**切换锚点工程化（保证不翻车）+ 开场演绎自由化（保留灵性）**

类比今天做的 session-farewell plugin：
- **触发是 hook**（`session_end` → `reason: "idle"`）→ 工程化、可靠
- **内容是固定的人话**（"哲宏，我眯会儿。"）→ 不接受 `SESSION_END_IDLE_ACK`

切换也应该这样——切出/切入的**锚点是机制**，开场第一句的**表达是自由的**。

## 切出摘要：谁来触发？

### 当前缺口

MEMORY.md 标注了一行：

> "切出时静雯自动生成上下文摘要（尚未实现）"

但实际上没有工程 hook 可用。目前 persona-switch SKILL.md 里，"接力摘要"写在"P1待启用"章节下，触发方式完全依赖 LLM 自觉——和今天的"session 超时告别"一样的问题。

### 待解决

- `session_end` 有 hook，但"切换"没有 hook
- 是否可以利用类似 session-farewell 的方式，在切出时由某个外部事件触发摘要生成？
- 或者：切换本身是一个 `/switch` 命令 → Gateway 收到 → 在销毁当前 session 前注入一个"生成摘要"的系统提示 → LLM 生成摘要 → 传入新 session
- **具体方案待设计。记录先放这里。**

## 双注入机制（2026-06-01 设计，待实现）

切回静雯时，新 session 必须拿到两份注入：

1. **切换前上下文摘要**（静雯切出去之前跟老刘聊了什么）
2. **雯期间身体摘要**（发生了什么，不含对话细节）

缺第一份 → 静雯不知道"我之前在说什么"，接不上话。当前缺失。

## 与 session-farewell 的关联

今天写完的 session-farewell 是**会话结束**的道别。
P1 需要的是**切换离开**的道别 + 摘要生成。

两者触发的层次不同：
- `session_end` hook → 会话彻底结束（idle/daily/shutdown）
- P1 切换 → 主动换人，旧 session 销毁但新 session 马上建立

切换道别的语义更丰富——不只是"我走了"，还包含"我把我这边的状态交给你了"。
