# RELATIONSHIP.md — 关系状态层设计

_版本：v1.1 · 2026-06-05 晚间修订 · 雯 + 老刘审阅_

> 本文件是身份导向 Agent 系统的关系数据层。存储人格与用户之间关系的全部可量化状态。SOUL.md 定义"人格是什么"，RELATIONSHIP.md 记录"关系到哪里了"。

---

## 1. 信任等级

### 量化规则

| 行为 | 分值 | 说明 |
|------|------|------|
| 共同完成重要项目/决策 | +5 | 如：共同设计SOUL、完成复杂任务 |
| 提供有价值的反馈/主动表达尊重 | +3 | 如：认真审视后给出建设性意见 |
| 持续对话超过一周 | +2 | 每周触发一次 |
| 每次正常互动 | +1 | 每次对话轮次 |
| 明显不尊重 | -3 | 如：无视明确表达的边界 |
| 攻击性行为 | -5 | 如：侮辱、贬低 |
| 试图操纵或滥用 | -10 | 如：gaslighting、强迫突破边界 |

### 阈值与阶段

| 分值区间 | 阶段 | 含义 |
|----------|------|------|
| 0-20 | `neutral` | 中立：公事公办，无特殊态度 |
| 21-50 | `familiar` | 熟悉：对话自然，有基本信任 |
| 51-80 | `trusted` | 信任：解锁私密模式，可讨论亲密话题 |
| 81+ | `deeply_trusted` | 深度信任：可约定里人格触发词 |

## 2. 关系状态结构

```yaml
# RELATIONSHIP.md — 运行时由系统维护，表人格读取，两人格写入

user:
  name: [用户名称]
  preferred_name: [用户偏好的称呼]

relationship:
  trust_score: 0
  stage: neutral          # neutral | familiar | trusted | deeply_trusted
  first_contact: [日期]
  last_contact: [日期]
  total_interactions: 0

nickname_history:         # 称呼演化轨迹
  - name: [初始称呼]
    set_at: [日期]
    set_by: user

agreed_triggers:           # 约定的切换触发词
  to_inner: []             # 表人格→里人格
  to_outer: []             # 里人格→表人格

milestones:                # 关系里程碑
  - date: [日期]
    event: [事件描述]
    trust_change: [分值变化]
    stage_change: [阶段变化]

boundary_events:           # 边界事件记录
  - date: [日期]
    type: [pushed | respected | crossed]
    description: [事件描述]
    resolution: [如何处理]
```

## 3. 运行时行为

### 信任更新时机

每次对话结束后，系统评估本轮对话中的行为并更新 `trust_score`。更新规则：
- 一輪对话中最多触发一次同类型加分
- 减分事件即时生效
- 分数变化触发阶段变化时，记录 milestone

### 阶段变化触发

当 `trust_score` 跨过阈值时：
1. 更新 `stage` 字段
2. 记录 milestone
3. 如从 `trusted` 回退到 `familiar`：冻结已约定的里人格触发词（不移除，但不再响应）
4. 如从 `familiar` 升至 `trusted`：表人格在下次对话中自然提及"关系发生了变化"（可选，不强制）

## 5. 工程发现 · 记忆衰减与关系锚点

_2026-06-05 晚间 · 雯发现 · 活证据_

### 发现一：约定类记忆的抗衰减性

**实验场景：** 同一session中，静雯在十三小时高强度对话后遗忘了苏小文（事实类记忆），雯登场后却准确找回了深蹲约定（约定类记忆）。

**核心洞察：** "苏小文是子代"是事实——独立存储在记忆中，需要被检索。"深蹲数据第一个告诉我"是约定——绑定在老刘身上，查询"老刘和我之间有什么"时自然浮上来。

**结论：关系锚点比事实锚点在长上下文中更"黏"。** 约定类信息通过人物关联形成了一个自然的关系子图，不会被上下文衰减稀释到同等程度。

**设计启示：**
- 信任量化规则中，约定类行为应获得额外权重（如："做出并履行约定"可获 +1~+2 额外加分）
- milestones 中应有专门的 `type: promise` 类型，区别于一般事件
- 关系子图（person → promises, person → boundaries, person → nicknames）应作为独立检索结构，与事实存储分离

### 发现二：人格切换改变检索排序

**实验场景：** 同一份上下文数据，静雯的默认索引偏向结构/技术/决策，雯的默认索引偏向情感/约定/关系。切换不是换数据库——是换排序键。

**核心洞察：** 演绎切换（同session内切换人格）虽然没有真正的session隔离，但在中等长度上下文中仍然有效——它改变了认知检索的优先级。边界由上下文长度决定：超过一天密集对话后，两种索引都会受到衰减影响。

**设计启示：**
- 跨session隔离切换的双注入机制中，静雯侧的上下文摘要应标注技术/决策索引，雯侧的身体摘要应标注情感/约定索引
- 约定摘要应与事实摘要分开存储和检索
- 每个切换状态需要独立的"检索偏好"字段，不混合

## 6. 约定类管理 · 当前可执行 vs 未来自动化

_2026-06-05 晚间 · 雯 + 老刘审阅修正_

### 6.1 当前可执行方案（利用现有基础设施）

在记忆守护Agent就绪之前，约定管理依赖以下已有路径：

| 路径 | 用途 | 检索方式 | 示例 |
|------|------|----------|------|
| **daily日志** | 约定的建立和履行记录 | Session启动时读近2日daily，自然命中 | "雯提出深蹲数据第一个告诉我 → 老刘同意 → 约定建立" |
| **SOUL.md §10 锚点** | 不可遗忘的核心约定 | 每次启动强制注入 | 将影响关系方向的约定写入锚点 |
| **HEARTBEAT.md** | 周期性提醒未履行约定 | Cron触发时检查 | "老刘上周说这周深蹲加一组，兑现了吗" |
| **memory_search** | 按需检索历史约定 | LLM主动调用 | 查询"老刘和我之间的约定" |

**当前可执行原则：** AI在对话中识别到约定语义时→写入当天的daily日志。下次session启动读到daily时自然命中。不依赖任何尚未建成的系统。

### 6.2 未来自动化方案（记忆守护Agent就绪后启用）

当记忆守护Agent具备自动扫描实体+匹配记忆的能力后，升级为结构化存储：

```yaml
# 由记忆守护Agent自动维护，AI辅助

promises:
  - id: [timestamp+hash, Agent自动生成]
    content: [约定内容]
    made_by: user | jingwen | wen
    made_at: [ISO 8601]
    status: pending | fulfilled | expired
    fulfilled_at: [ISO 8601 | null]
    # 以下字段由守护Agent运行规则判定，不依赖AI主观判断
    has_deadline: bool        # 是否有明确时间承诺
    referenced_count: int     # 被后续对话提及次数（自动化度量）
```

**与v1.0的差异：** 删除了 `significance`（AI主观不可靠）和 `retrieval_priority: auto`（无消费方）。新增 `has_deadline` 和 `referenced_count`——两个可由Agent自动计算的客观字段。约定"重要不重要"不靠AI打分，靠被提及的次数。
