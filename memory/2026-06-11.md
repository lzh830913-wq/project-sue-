  - 根源定位：60分钟闲置超时（session.reset.idleMinutes=60）自动杀session→老刘下班到晚上之间session被杀→跨session信息丢失

- 候选方案：session.reset从idle模式改为daily模式，atHour=4（凌晨4点自然刷新一次），取代60分钟闲置杀session。

- **关键发现——文档揭示双模式机制（config-agents.md §Session）：**
  - `reset` 可同时配置 `mode: "daily"` + `atHour` + `idleMinutes`
  - 文档原文："When both configured, whichever expires first wins."
  - **推论：服务器上可能有 `mode: "daily", atHour: 4` 的隐式默认值在起作用！** 如果daily模式在凌晨4点刷新session，而idle模式的60分钟也同时生效（两者竞速，先到先触发），那么：
    - 白天8:30-下班间如果频繁聊天 → idle一直不触发 → session活到晚上
    - 凌晨4点daily刷新 → 新一天session
  - 但Mac上可能只有idle模式（没有daily保底）→ 下班-晚上间超过60分钟无人聊天 → idle触发 → session被杀 → 失忆
