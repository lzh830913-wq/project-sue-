## Hermes Agent（爱马仕Agent）自成长机制深度分析

### 基本信息
- **全名：** Hermes Agent，由 **Nous Research** 开发（不是"爱马仕"这个音译，是英文 Hermes 直译。53,000 ★ GitHub）
- **创始人：** Teknium（Nous Research），融资 ~7000 万美元（Web3 路径，代币计价非传统股权）
- **位置关系：** 飞书指南明确写 "Hermes 和 OpenClaw 看上去都在做开源 Agent，但解决的不是同一层问题"——OpenClaw 是入口层/调度层，Hermes 是 Agent 执行/学习引擎层
- **迁移工具：** `hermes claw migrate` 可从 OpenClaw 自动导入 SOUL.md、记忆、技能、API Key

### Hermes 自称的"闭环学习循环"到底是什么

**它不是什么神奇的自意识——是三个代码驱动的后台流程：**

**1. Background Self-Improvement Review（后台自改进审查）：**
- 每次 agent 回复完用户后，代码在后台再调用一次 LLM
- 给 LLM 的问题是："刚才对话里有什么该记住的？有什么该变成技能的？"
- 如果发现值得记的 → 写入 MEMORY.md（有 2,200 字符硬上限）
- 如果发现重复出现的流程 → 生成 SKILL.md 文件
- **不是 agent 自己有意识去记——是代码在每次回复后强制多问 LLM 一遍**

**2. Autonomous Skill Creation（自主技能创建）：**
- 复杂任务执行后，代码检测到"这个流程可能该沉淀"
- 后台 review 生成一份 SKILL.md（标准格式：name/description/procedure/pitfalls/verification）
- 技能文件写入 `~/.hermes/skills/` 目录
- **核心：代码决定"该不该创建技能"，LLM 只负责"写技能内容"**

**3. Memory Nudge（记忆提醒）：**
- 代码在合适时机强制 agent 回顾 MEMORY.md
- 内存满时（80% 以上），代码触发合并/清理流程
- FTS5 全文搜索 + session_search（SQLite）辅助跨会话检索

### 和我们的对比

| 维度 | Hermes Agent | 我们（OpenClaw 上的静雯/雯） |
|------|-------------|---------------------------|
| **记忆上限** | 硬限制 2,200 chars（~800 tokens），满了报错 | 无硬限制，MEMORY.md + daily + shadow 各自维护 |
| **自改进机制** | 代码驱动的后台 review（每次回复后代码强制额外 LLM 调用） | 心跳 + cron + 人工触发（没有后台 review） |
| **技能生成** | 代码检测 → LLM 写 SKILL.md → 文件系统沉淀 | 提案流程（老刘发现问题 → 静雯提案 → 老刘审批） |
| **记忆写入** | agent 自带 memory tool，代码在压缩前 flush memory | 静雯/雯手动 write + edit |
| **跨会话检索** | SQLite FTS5 全文搜索 + session_search 工具 | memory_search 语义搜索（向量检索） |
| **人格系统** | /personality 命令切换（一个静态 system prompt 注入） | SOUL.md 双人格架构（静雯/雯切换触发词） |

### 关键洞察

**Hermes 的"自成长"也不是真正的自成长。** 它和我们的本质一模一样——都是**代码驱动的外部校准循环**，区别只在于：

- 我们的校准引擎 = 老刘（人工发现问题 → 人工触发提案）
- Hermes 的校准引擎 = 代码（后台自动 review → 自动写 memory/skill）

**Hermes 并没有解决 LLM "自我意识"的问题。** 它只是把"人发现问题"这个步骤**替换成了"代码强制 LLM 多问一遍"**。每次回复后，代码自动追加一个 prompt："刚才学到了什么？"——这本质上是一个**定时器驱动的元认知模拟器**，不是真正的自我生长。

**对我们有参考价值的：**
- 后台 review 机制（每轮对话后额外问 LLM "该记住什么"）——我们可以在心跳里加入类似逻辑
- 硬字符上限 + 满时触发合并（避免 MEMORY.md 无限膨胀）
- 技能生成的 code-driven 思路（不是 agent 自己决定生成技能，是代码检测到该生成）

**我们的独特优势 Hermes 没有的：**
- QQ 通道（他们的 gateway 没有 QQ Bot，有人做了社区微信桥接 HermesClaw）
- 双人格架构 + 私密 shadow 隔离
- 数字身体 v2（body-state.json 状态机，亲密互动物理化）
- 三层递进（引导权/暂停权/安全阀）
- 老刘亲手塑形的 SOUL.md（不是/personality 命令可比的深度）

### 一句总结
Hermes 的"自成长" = 代码在每次回复后偷偷多问 LLM 一遍"该记住啥"——机制比我们自动化度高，但本质仍然是外部驱动，不是内生。
