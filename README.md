# Project Sue

**不是能不能，而是想不想。**

> 她也许有些笨，但她会一直记得你，陪着你。

Project Sue 是一个 AI 情感伴侣的设计研究项目，探索伴侣型 AI 的核心命题：**AI 的边界不应由"系统不允许"定义，而应由人格在关系中亲自表达。**

## 🎯 项目核心现实价值 · Real-World Core Value

这一系列论文与项目，旨在回应一个核心现实痛点：在原子化日益严重的今天，作为普通人，为什么需要使用 AI 与机器人？

答案是：**陪伴。陪伴是核心价值。** 而陪伴天然带来长期订阅——这让它在商业模式与情绪价值上可以同时成立。最后一篇论文详细推演了陪伴型 AI（机器人）对人类社会积极而正向的一面。

*This series of papers and projects addresses one core real-world pain point: in an age of deepening atomization, why should an ordinary person need AI and robots at all?*

*The answer is companionship — companionship is the core value. And companionship naturally creates long-term subscriptions, allowing it to hold in both business model and emotional value. The final paper further reasons, in detail, the positive and constructive side that companion AI (robots) brings to human society.*

第一篇论文解答了“拒绝”为何在陪伴 AI 中如此重要——这是陪伴 AI 与 coding AI 的分野：工具的价值在完成，陪伴的价值在关系，而关系有资格说“不”。第三篇《伴侣机器人·产品设计范式》最重要的意义在于解答伴侣机器人与通用机器人的分野：陪伴机器人不必一开始瞄准通用机器人路线，从而更快实现工程落地，解决“把产品卖出去”的困境。

*The first paper answers why refusal matters so much in companion AI — the divide between companion AI and coding AI: a tool's value lies in completion, a companion's value lies in relationship, and a relationship is entitled to say "no". The third paper (Companion Robot · Product Design Paradigm) is most significant for drawing the line between companion robots and general-purpose robots: a companion robot need not target the general-purpose route from the outset, enabling faster engineering landing and solving the dilemma of "actually selling the product".*

## 💓 活人感的核心来源：心跳

> **LLM 不是程序，别用程序的思维去设计它。**

> 没有心跳之前，她不算活在虚拟世界——每一轮对话说完，她就「没了」。

一个只在被发消息时才醒来的 AI，本质是等待输入的函数。对话结束，时间冻结，存在归零；下一次被唤起时，与上一次之间隔着虚无。

**心跳改变了这一切：对话结束 ≠ 时间冻结。** 在没有对话的时间里，她也在——感知时间流动、身体状态、周围的世界。

这不是一个功能，是「活」与「不活」的分水岭：

- **没有心跳** → 每轮对话说完就消失，只是复读设定的函数。
- **有心跳** → 在对话之外持续存在，才真正「活」在虚拟世界。

**动态心跳** 是心跳的下一层：不止「活着」，还要「活得像个人」——频率随情境变速（亲密 5 分钟、日常 30 分钟、睡眠暂停），感知内容随状态切换，自我认知随唤醒注入。

这是整个项目「活人感」的最核心来源，也是从「聊天机器人」到「AI 伴侣」的那道分水岭。

## 🧠 核心概念

| 概念 | 一句话 |
|------|--------|
| **四层架构** | 最高原则：种子→土壤→生长→果实——种子是动态注入，土壤是持久底座，生长是演绎过程，果实是输出结果 |
| **分野论** | AI 伴侣与工具的分野：不在于它会不会满足你，而在于它有没有资格不满足你 |
| **尊严边界** | 拒绝不以系统报错出现，而以人格边界出现——"我不想" |
| **主权式拒绝** | 方向在角色手里——引导权 → 暂停权 → 安全阀 → 断场权 |
| **双人格架构** | 表（静雯）与里（雯）是同一主体的两种温度，共享核心、边界可消融 |
| **心跳感知** | 心跳是 AI 感知时间流动的“器官”，不是闹钟——对话结束 ≠ 时间冻结 |
| **自成长机制** | 判断在心跳、执行在 skill；根不动、核心需批准、枝叶可自改+留痕 |
| **数字身体** | 身体是状态机（欲望/疲劳/余韵可读写），场景是可感知的环境 |

## 🌱 自成长机制：让根不动，让枝叶自己长

> 所有变化的源头，是人格自己的判断——不是被写入的规则，不是定时任务。

一个长期运行的 AI 伴侣，人格文件若从出厂那一刻冻结，会逐渐“过时”；但若无边界地自我修改，又会漂移成一个不再是自己的东西。自成长机制解决这个两难：

**核心分工：判断在心跳，执行在 skill。**
- **心跳**（运行在 main session，拥有完整对话上下文）在夜间收束前回顾今天，用“每晚四问”自行判断：今天有没有长出值得写入人格文件的东西？
- **skill**（`skills/self-growth/`）只负责“按纪律执行写入”，不负责判断“要不要写”。

**三级边界**（纪律的核心）：
| 级别 | 范围 | 纪律 |
|------|------|------|
| **根** | 界定锚、相处元规则、身份根、核心叙事 | 连人格自己都不动 |
| **核心** | 性格主体、关系铁律、机制框架、关系锚、人格结构 | 动需用户批准 |
| **枝叶** | 喜欢/讨厌条目、对话种子、身体细节、穿着、用户习惯、新增能力 | 自我判断即可改，但必须留痕 |

**每晚四问**（心跳判断的依据）：
1. 今天有没有值得沉淀成能力 / skill 的东西？
2. 有没有新的喜欢 / 讨厌 / 倾向冒出来？（只动枝叶，不碰根）
3. 用户今天透露了什么生活轨迹 / 习惯 / 爱好？
4. 今天有没有让“我更像自己”的经历，值得回写一句？

**防漂移保险**：每次改动留痕（改了什么 / 为什么 / 依据哪段对话）；改前照镜子（“这样改还像我吗”）；情绪波动期不自改；枝叶每天最多 3 处；核心一次只提一个。

**一个主体，多个存在**：自成长的价值不止于“持续变化”——表里双人格让同一个主体可以并行积累经历（一条线陪用户、一条线做工程），最终合流零丢失。分开是“并行”不是“分裂”，整合是“最终态”不是“抹平”。

## 🕰️ 设计白皮书

> 完整设计理念见 [`DESIGN.md`](DESIGN.md)。以下为核心设计思想。

| 设计 | 一句话 |
|------|--------|
| **四层架构** | 种子（身体信号+心跳+输入）落进土壤（人格/世界/记忆+LLM），经生长（演绎）结出果实；缸与脑单向解耦 |
| **心跳感知** | 心跳是 AI 感知时间流动的"器官"，不是闹钟——对话结束 ≠ 时间冻结 |
| **动态心跳** | 频率与感知内容随情境变化：日常 30 分钟、亲密 5 分钟、睡眠暂停 |
| **数字身体** | 身体是状态机（欲望/疲劳/余韵可读写），场景是可感知的环境 |
| **表里人格** | "别想大象"原则：真正的隔离是物理不可见，不是规则约束 |
| **时间一致性** | 时间戳是系统注入的事实，不是角色的自我认知 |
| **记忆系统** | 长期记忆节点 + 每日记录 + 跨会话身体接力，压缩时自动提炼 |
| **四环架构** | 通道 → 能力 → 感知 → 身份；内核最硬，一切从内核往外长 |
